# Releasing the native app

The Android app updates itself from GitHub Releases. On every cold start it asks
`https://api.github.com/repos/<owner>/<repo>/releases/latest` whether there is a
newer version, and if so offers to download the release's `.apk` asset and hand
it to Android's package installer. There is also a **Check for updates** button
under Settings → Updates.

## One-time setup

### 1. Create a release keystore

Android only installs an update over an existing app when both APKs are signed
with the same key. Expo's template signs release builds with a throwaway debug
keystore that is regenerated by `expo prebuild`, so releases need their own key:

```bash
keytool -genkeypair -v \
  -keystore shelvarr-release.keystore \
  -alias shelvarr \
  -keyalg RSA -keysize 2048 -validity 10000
```

Keep this file safe and backed up. Losing it means every user has to uninstall
and reinstall the app to move to a new key.

### 2. Add the repository secrets

Under **Settings → Secrets and variables → Actions**, add:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 shelvarr-release.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | The keystore password |
| `ANDROID_KEY_ALIAS` | `shelvarr` (or whatever alias you chose) |
| `ANDROID_KEY_PASSWORD` | The key password |

### 3. Move your phone onto the release key

An app already sideloaded from a locally built APK carries the debug signature,
so the first release cannot install over it. Uninstall the app once, then
install the first release APK by hand. Every release after that updates in
place.

## Cutting a release

1. Bump `expo.version` in `apps/native/app.json` and commit it.
2. Tag the commit and push the tag:

   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```

The `Release Native App` workflow then:

- checks the tag matches `expo.version` (it fails loudly if you forgot step 1),
- derives `android.versionCode` from the version (`major*10000 + minor*100 + patch`),
- runs `expo prebuild` and builds a release APK signed with the keystore above,
- creates the GitHub release if the tag doesn't have one, and uploads
  `shelvarr-<version>.apk` to it.

Within a few hours every phone running the app offers the update on its next
launch.

## Building signed APKs locally

The signing config reads the keystore from the environment at Gradle time, so a
local build can produce the same artifact:

```bash
export ANDROID_KEYSTORE_PATH=$PWD/shelvarr-release.keystore
export ANDROID_KEYSTORE_PASSWORD=...
export ANDROID_KEY_ALIAS=shelvarr
export ANDROID_KEY_PASSWORD=...
pnpm --filter @shelvarr/native build
```

Without those variables the build falls back to the debug key, exactly as before.

## Pointing the updater at a fork

The repository is baked in at build time. To build against a fork, set
`EXPO_PUBLIC_UPDATE_REPO=your-user/your-fork` before building.
